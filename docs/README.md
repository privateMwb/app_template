# docs/

Documentation for this project: the generated API reference, and
the source files/assets that reference lives in.

## Contents

- **`Doxyfile`** — Doxygen config that generates HTML API
  reference docs from `backend/include/` and `backend/src/`. See
  the comments at the top of the file for what to retarget when
  starting a new app from this template (just `PROJECT_NAME` and
  `PROJECT_BRIEF`).
- **`assets/`** — diagrams, screenshots, and other images
  referenced from documentation (this file, or generated docs).
  Not fetched/generated content — anything checked in here is
  meant to stay.
- **`html/`** *(generated, gitignored)* — Doxygen's output.
  Not committed; regenerated by CI or locally, see below.
- **`doxygen-awesome-css/`** *(generated, gitignored)* — the
  Doxygen Awesome theme, fetched fresh on each generation rather
  than vendored.

## Generating docs locally

From the repo root:

\`\`\`bash
cd docs
git clone --depth 1 https://github.com/jothepro/doxygen-awesome-css.git
doxygen Doxyfile
\`\`\`

Output lands in `docs/html/`. Requires `doxygen` installed, and
optionally `graphviz` for class/include diagrams (`HAVE_DOT`) —
Doxygen skips diagram generation harmlessly if it's missing.

In CI, `.github/workflows/docs.yml` does the same and publishes
`docs/html/` to GitHub Pages.

## Repository layout

For reference, where things live across the whole repo and why:

- **`.github/assets/`** — README badges, social preview image.
  Rendered by GitHub directly from the README; not part of any
  build.
- **`docs/assets/`** — diagrams and screenshots referenced from
  documentation (this folder).
- **`frontend/src/assets/`** — icons/images the UI actually
  imports; processed, optimized, and hashed by Vite at build
  time. Not for anything that isn't imported by frontend code.
- **`frontend/public/`** — static files served as-is, unprocessed
  (favicon, robots.txt, etc.).

The rule of thumb: an asset lives next to whatever consumes it,
so each part of the repo (`.github`, `docs`, `frontend`) stays
self-contained and can be reasoned about — or extracted — on its
own.
